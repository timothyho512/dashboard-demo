DBQ Console · three concept directions

One database queue, three ways to look at it.

AIS writes work items into shared tables and MMP claims them, so the producer never waits on the consumer. When something goes wrong in between, nobody has a console to see it. These prototypes replay the same invented Thursday through three different consoles, each built for a different person and a different question.

Every page has the same replay bar: press play, drag through the day, or jump to a story moment below.

The day in the sample data

Thu 15 Oct 2026, invented. Each link opens that moment in that concept.

Behind the prototypes

The queries are real and were run against 1.6 million synthetic rows on PostgreSQL 17.

report.mdWhat each concept is for, prior art, light-bulb ideas, the SQL behind every panel, build options and a first version to build. sql/panels.sqlOne query per panel (P1 to P18), plus the claim, heartbeat and fenced completion they rely on. sql/schema.sqlThe assumed queue table and optional helper tables, each index labelled with the panels that need it. sql/dialects.mdOracle 19c and SQL Server versions of the key queries, and what behaves differently there. sql/seed.sqlDeterministic synthetic data that reproduces the day's story for the SQL. prototype/assets/sim.jsThe simulated day, minute by minute.
